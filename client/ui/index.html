      Throwaway machines for Pi
      
        
        
          
      • Pi is root there: packages, services, Docker, all allowed. It stays in its own sandbox and drives them from there.
        • 
          
      • Nothing of your VM or home: only what Pi copies in.
        • 
          
      • Gone after their lifetime; Reset brings one back clean. Every command Pi runs there is written in the Labs tab.
        • 
        
      
        
      Then add a lab host: a VM with Incus.
      
      
      
      
      
        
      
      
      
      
      
      
      Then reconnect Pier, so the picker's next SSH login is in the incus group. For virtual machines too, set the VM's CPU type to host in Proxmox (Hardware > Processors).

        Networks
        
        
        The internet through the host, a VLAN of your firewall, or other labs only.
        
        
          
        
          
          How to add a network
          
          On the VM. Then let your account use it, with every network it should see (your own NAT, often incusbr-1000, included). The README tells it in full (Labs: networks).
          
          
          # a VLAN of the firewall, on a trunk card of the VM (Proxmox: no VLAN tag on it)
sudo incus network create pier-labs-30 --type=macvlan parent=ens19 vlan=30

# a network between labs only, without NAT
sudo incus network create lab-lan --type=bridge ipv4.address=10.50.0.1/24 ipv4.nat=false

# then, for your account
sudo incus project set user-$(id -u) restricted.networks.access=incusbr-$(id -u),pier-labs-30,lab-lan
