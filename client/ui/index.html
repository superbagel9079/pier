    Lab hosts
    
        
    Where labs are made: a VM with Incus. Another VM you add (Pier runs Incus there over SSH, with its key), or Pi's own VM if you choose it. New labs go to the default host, unless Pi or New lab… names another. No host, no lab.
    
        
      
        
      
          
          
        
      
        
      Limits
      
        
      
        
      Networks
      
        
      What a lab can be plugged into. Incus's NAT gives the internet through the lab host, and your firewall never sees the lab. A VLAN of your firewall makes the lab a machine of its own there: the firewall gives its address and applies its rules. A network between labs only has no way out: for a router, a DMZ, a VPN between labs. A lab can be on several at once (New lab…, or Pi's lab_create).
      
        
        
        
        
          Add a network (an admin, once for each)
          
        On the VM. Then let your account use it, with every network it should see (your own NAT, often incusbr-1000, included). The README tells it in full (Labs: networks).
        
          
        # a VLAN of the firewall, on a trunk card of the VM (Proxmox: no VLAN tag on it)
sudo incus network create pier-labs-30 --type=macvlan parent=ens19 vlan=30

# a network between labs only, without NAT
sudo incus network create lab-lan --type=bridge ipv4.address=10.50.0.1/24 ipv4.nat=false

# then, for your account
sudo incus project set user-$(id -u) restricted.networks.access=incusbr-$(id -u),pier-labs-30,lab-lan
